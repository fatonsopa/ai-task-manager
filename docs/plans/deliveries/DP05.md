### Important terms

An **owner** is the retained process authorized to coordinate a configured workflow. An **attempt** is an individual worker execution; owner replacement does not itself authorize another attempt. A **recovery request** selects a bounded action against original durable identities. A **successor** is a separately authorized run with an immutable predecessor link, fresh key and finite deadline. A successor never edits the predecessor's authority or historical result. **Quiescent** means every required worker, command, host, collector and merge consumer has a verified stop disposition; owner absence alone is insufficient. A **known effect** has canonical identity and authoritative outcome evidence. An **unknown effect** may have occurred and cannot be repeated merely because its reply is missing.

### Recovery interface and authority

Retain the existing literal `aitm workflow run --input request.json` and `aitm workflow resume --input request.json`, with configured session and original request schemas. A healthy owner continues through those operations. Existing `WorkflowService.recover_expired(RecoveryAuthorization)` is trusted code-only; it is not an existing CLI command.

Propose one installed operator entry for DP05:

```sh
aitm --config <service.json> --installation <recovery-installation.json> --json workflow recover --input <request.json>
```

This is a planned command, unavailable in accepted DP04. T01 must implement and document it before any demonstration claims it ran. Its sealed installation resolves trusted typed authority; the request selects only `inspect`, `resume`, `stop`, `successor` or `retire`, an original workflow/effect/resource reference and an operation key. It cannot supply arbitrary commands, paths to adopt, model-selected permissions, proof objects or a replacement journal. The configured plan fixes allowed work and resources. Extend the existing application service and installer/CLI composition, with ordinary CLI/MCP sharing the same Core policy. Model-facing MCP cannot mint operator authority; expose only operations allowed by its verified installed capability. Literal CLI, installed API, MCP fixture checks and genuine managed-host observations are reported separately.

Use three distinct permissions within existing authority/journal mechanisms: scoped observation; settlement/stop/retirement of exact recorded obligations; and fresh execution for an explicit successor. An expired or revoked execution grant cannot authorize any of them. Current trusted operator authority may separately authorize bounded settlement of an old owned obligation, while the old grant remains expired/revoked. Fresh execution requires current human/delegated start authority and exact scope/version/decision binding. Administrative evidence access never becomes task-content or execution permission.

Admission and each effect recheck current authority, source/configuration, original store continuity and current human decisions. Serialize through existing setup/task/workflow claims; hold no Core transaction over provider calls, process waits or Git operations. A verified dead owner with a stale socket needs an identity-checked installer retirement/replacement path; generic client failure never elects an owner. Preserve old descriptors and stop evidence. A replacement binds fresh endpoint/owner identity to the original installation and journals, without rewriting their recorded origins. Same still-valid execution authority may support continuation only when its original plan/deadline/source binding remains valid; otherwise require a successor.

Reobserve exact recorded process identities and required descendants using trusted host/runtime adapters. PID reuse, an unavailable observer, incomplete containment or unknown child ownership prevents signaling and release. When an orphan is verifiably still owned, a separately authorized stop may settle it; cold recovery must not invent a waitable handle, terminal output or model success. A next attempt requires complete quiescence and current eligibility, retaining the interrupted attempt and checkpoint.

| State and interruption boundary | Required recovery result |
| --- | --- |
| Lost reply, owner still live; before/after durable workflow intent | Reconnect to the verified owner and original key/reference. Return saved result or continue its owned operation. Another client never creates another owner or intent. |
| Owner verified dead; before/after reservation or worker start | Inspect all original journals and actual process/resource facts. A proven unsent start can continue under original valid authority; a canonical reservation is reconciled, not repeated. | Hold, cancellation, reassignment or changed scope; during startup/execution/recovery | Fence obsolete work first, preserve the newer decision, observe actual stopping and settle the correct permitted destination. Cancellation needs its reason/evidence; a hold is not cancellation. Foreign reassignment permits no new foreign content access or automatic successor. |
| Known provider mutation, missing acknowledgement; after send/before readback | Use the original operation, canonical target and approved content for independent readback. Record recovered confirmation without sending again. Confirmed comment and unresolved label remain separate. |
| Unknown send/create/label effect | Retain intent, send history, original key and uncertainty. Read canonical identity only if supported evidence exists. Missing identity is not permission to search by title, resend a create or remove a candidate. Only an independently proved never-sent effect can use its original authorized retry. |
| Partial files/checks/commit; before/after commit intent | Preserve dirty files, untracked work, candidate commits, work units and checks. Reuse a check only when its exact artifact/inputs still match. Continue remaining work through the owned candidate or explicitly authorized lineage; no reset/clean or foreign branch adoption. |
| Publication moved the configured target; before/after acknowledgement | Reconcile original publication intent against actual target ancestry/content and recorded authority. Preserve a proven merge while Linear/report/cleanup remain pending. Divergence or unknown publication blocks dependent replay; target-advance lineage cannot rewrite frozen publication. |
| Expired or revoked execution authority; before any next effect | Observe/settle only with distinct current recovery authority. A fresh successor requires explicit finite authority and the reconciled predecessor. Old keys return old history and grant no new effect. Revocation itself is never reversed. |
| Reporting interrupted after business effect or host delivery | Resume the original scoped event and missing receipt stage. Do not repeat business work or infer AI acknowledgement/user reporting from delivery/cursor movement. |
| Cleanup interrupted before/after removal or provider archive | Inspect original release intent, last consumers and current ownership; confirm actual removal/readback under finite current recovery authority. Keep unknown/foreign/changed resources protected. |
