### Interfaces and implementation boundary

Keep the existing installed commands:

```sh
aitm --config <service.json> --json workflow run --input <request.json>
aitm --config <service.json> --json workflow resume --input <request.json>
aitm --config <service.json> --installation <installation.json> --json workflow recover --input <request.json>
```

The sealed trusted plan chooses task, host, resource declarations, allowed workflow and merge target. Run selects `task_id`, `plan_ref` and original `operation_key`; resume uses `workflow_ref`; recovery follows DP05's exact installed schema. Ordinary run and resume resolve their installation through the trusted registry; the CLI accepts `--installation` for recovery. These commands do not let a model invent paths, check selections, ownership, priority overrides or authority. Reuse the current scheduling explanation and service projections; add only typed fields and supported composition needed by the approved behavior. Any changed public schema gets the corresponding Interface Contract (IC), consumer checks and compatible migration before use.

Keep provider/network/process/Git work outside Core transactions. Atomic claim, capacity and conflict reservations share the existing admission transaction; physical resource effects use existing durable intents, ownership receipts and reconciliation. Release only after confirmed stop and last consumer. If persisted fairness/conflict facts require a schema addition, preserve old rows/events, define conservative defaults for unknown declarations, prevent stale writers and test repeat/crash migration once. Rolling back code cannot erase later reservations, human decisions or publication history; stop admission and roll forward or use the supported recovery path.
