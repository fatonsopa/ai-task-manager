### Proposed operator interface

Add two explicit trusted operator commands to the installed CLI. They are proposed interfaces, not commands already available in the current candidate:

```sh
aitm --config CONFIG session setup --input SETUP_REQUEST
aitm --config CONFIG --json session doctor
```

`session setup` creates the initial private configuration when absent and establishes the session through the existing trusted setup API. Its versioned, closed-schema request explicitly selects the state directory, expected Linear identity/project/team, logical session, stable agent connection, one supported credential reference, approved external writing package/interpreter and pins, finite capacity, permitted actions, absolute finite deadline and operation key. Request credentials are references, never secret values. The request cannot import Python factories, arbitrary executables, observer verdicts, signed records or a caller-selected database capability. No arbitrary JSON approval is accepted as writing approval.

For DP01, explicitly delegate only `enqueue`. New-task creation still requires the exact writing approval. An approved writing source is a separately installed pinned prerequisite; this work does not distribute or modify the source skill. The command captures/verifies that source and derives its approval policy using the existing `WriterPackage` contract, rather than accepting fabricated policy hashes. It validates the selected interpreter and finite inputs before publishing authority. Use physical private directories and mode-0600 files. Authoritative state resides outside the installed package, caches and the fresh project's files. Owner record/socket paths and instance identity are generated and bound before setup; path limits and ownership remain enforced.

When configuration exists, exact replay uses the existing setup identity/history rules. Changed scope, source, capacity, delegation or deadline with the same key refuses. Initial setup cannot overwrite another installation, re-elect a copied/replaced claim store, erase history, renew an expired grant or reopen preparation after owner activation. Renewal remains a separate existing trusted recovery contract; this command provides no new renewal mode. An interrupted setup retains its intent and owned partial files; report the exact reconciliation need without resetting state or falsely reporting rollback. A new manifest parser and thin installation adapter are proposed; Core and provider policy remain authoritative.

`session doctor` checks the selected installation's package/configuration, writing pins, private paths, claim-store enrollment, signed provider/session authority, current provider identity/connection, finite persisted capacity and preparation eligibility. It returns sanitized per-check verdicts and an overall failure when a required check fails. It performs no task mutation, capacity installation, owner activation, enrollment, renewal, repair or implicit fallback. Its local checks use read-only access; live identity checks are read-only provider queries. Unavailable observations report unavailable/blocked rather than inventing readiness. It must not turn a diagnostic into a general owner-free task API.

Continue using the existing `workflow prepare` envelope, without adding a second intake engine. The operator follows prepare→review→finalize for exact task prose, then submit, inspect, explicitly enqueue and inspect again. The writing review is an actual semantic review against the frozen source and guidance; a passing mechanical check or a copied positive JSON verdict cannot substitute for it. Existing ordinary CLI/MCP calls continue to require their configured owner.

The command spelling, bounded setup manifest and wheel-based delivery above are recommended choices included in `DP01-AGREEMENT`. No separate architecture or infrastructure purchase is proposed.
